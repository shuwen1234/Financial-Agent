# 21 天每日代码导读

这份导读对应本仓库的**虚构合同/合规档案**。每天按“看入口 → 顺着函数调用 → 跑命令 → 解释输出”的顺序学习。不要把实验模块说成已部署的主服务，也不要用虚构样本的指标替代真实业务指标。

## 每天开始前

在 `financial-agent/` 根目录打开 PowerShell：

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -m pytest -q
```

`$py` 每开一个新终端都要重新设置。主应用依赖装 `requirements.txt`；Milvus 实验额外装 `labs/requirements-milvus.txt`；SQL/审查实验额外装 `labs/requirements-light.txt`。BGE 和 Langfuse 只在相应日期按需安装。每天把运行命令、输出截图、自己能讲清的逻辑记到学习笔记，不必背代码。

## 第 1 周：状态图、Milvus、流式接口

### Day 01｜读懂主状态机

- **看：** [state.py](../app/agent/state.py) → [graph.py](../app/agent/graph.py) → [nodes.py](../app/agent/nodes.py)。
- **逻辑：** `START → plan → retrieve → grade`；证据不足且未达到两次检索就 `rewrite → retrieve`，否则 `synthesize → END`。`AgentState` 保存 `question/query/attempts/evidence/citations`，节点只返回需要更新的字段。
- **关键代码：** `builder.add_conditional_edges("grade", nodes.route, {"rewrite": "rewrite", "synthesize": "synthesize"})`。
- **跑：** `& $py -m pytest tests/test_agent_flow.py -q`。再从 [main.py](../app/main.py) 的 `chat()` 跟一次调用。
- **讲清：** `attempts` 是业务重试数；`recursion_limit` 是整张图的步数保险，两者不同。

### Day 02｜Checkpointer、人工审核、并行与死循环

- **看：** [langgraph_control.py](../labs/langgraph_control.py) 的三个函数 `interrupt_demo`、`fanout_demo`、`recursion_demo`。
- **逻辑：** `InMemorySaver` 通过 `thread_id` 保存暂停状态；`interrupt()` 把控制交给人工，`Command(resume=...)` 继续；`Send` 将两个子问题分发，`Annotated[list, operator.add]` 合并结果；死循环触发 `GraphRecursionError`。
- **跑：** `& $py -m labs.langgraph_control`。
- **讲清：** 本实验用内存 Checkpointer；主服务当前是单轮请求，没有持久化会话，也没有人工审核入口。

### Day 03｜Milvus collection 与 50 条片段

- **看：** [milvus_demo.py](../labs/milvus_demo.py) 的 schema、`upsert`、`search`。
- **逻辑：** `chunk_id` 是主键，`vector` 为 1024 维，`doc_id/parent_id/dept_scope/text` 是标量字段。先用可复现的哈希向量检查索引与 API，不把它当语义检索质量。
- **跑：** `& $py -m pip install -r labs/requirements-milvus.txt`，再跑 `& $py -m labs.milvus_demo`。会建立独立的 `data/milvus_lab.db`。
- **讲清：** Embedding 模型的输出维度必须等于 collection 的向量维度；本地 Lite 实验不代表集群部署经验。

### Day 04｜BGE-M3 真正向量化

- **看：** [milvus_demo.py](../labs/milvus_demo.py) 中 `if real_model` 分支、`BGEM3FlagModel.encode(...)["dense_vecs"]`。
- **逻辑：** 相同的 50 条文本换成模型产生的 dense 向量，再比较三个问题 top5 的顺序。首次下载模型需要较多时间、内存和磁盘。
- **跑：** `& $py -m pip install -r labs/requirements-models.txt`，再跑 `& $py -m labs.milvus_demo --real-model`。
- **讲清：** Embedding 负责粗召回；不要声称哈希向量有语义能力。**真实 BGE 路径须你在本机跑通并记录输出后再写进自己的经历。**

### Day 05｜权限标量过滤、更新与删除

- **看：** [milvus_demo.py](../labs/milvus_demo.py) 的 `filter_expr`、`upsert`、`delete`；主服务的 [auth.py](../app/services/auth.py) 与 [retrieval.py](../app/services/retrieval.py)。
- **逻辑：** 实验用 `dept_scope in ['all']` 和 `['all','legal']` 比较结果；主服务先按租户、角色、密级、生效日期过滤，再排序，禁止无权限片段进入模型上下文。
- **跑：** `& $py -m labs.milvus_demo --scope all`，再跑 `& $py -m labs.milvus_demo --scope legal`。
- **讲清：** `upsert` 用同一主键更新片段；按 `doc_id` 删除对应档案重建索引。实验 collection 与主服务 SQLite 数据不相连。

### Day 06｜FastAPI SSE 节点事件

- **看：** [main.py](../app/main.py) 的 `chat_stream()`、`sse()`；[graph.py](../app/agent/graph.py) 的 `stream_updates()`。
- **逻辑：** `graph.astream(..., stream_mode="updates")` 逐节点输出，服务映射成 `plan/retrieve/grade/rewrite/token/citation/done`。`request.is_disconnected()` 与 `CancelledError` 处理客户端中断。
- **跑：** `& $py -m pytest tests/test_agent_flow.py -q`；启动 `& $py -m uvicorn app.main:app --host 127.0.0.1 --port 8000`，在 `/docs` 调用 `/v1/chat/stream`。
- **讲清：** 当前 `token` 是模型完成后拆分的显示片段；模型调用本身还不是逐 token 输出，断连也未保证立即中止正在执行的同步模型请求。

### Day 07｜Vue3 打字机与停止按钮

- **看：** [App.vue](../web/src/App.vue) 的 `ask()`、`handleFrame()`、`stop()`，以及 [vite.config.js](../web/vite.config.js) 的 API 代理。
- **逻辑：** `fetch` 读取 `ReadableStream`，按空行切 SSE 事件；`token` 追加到回答；`citation` 显示档案卡片；`AbortController.abort()` 断开请求。
- **跑：** 先启动后端；再在 `web/` 跑 `npm install` 和 `npm run dev`，打开终端给出的前端地址，导入示例合同、提问、点击停止。后端若是 8001，先设 `$env:VITE_API_TARGET='http://127.0.0.1:8001'`。
- **讲清：** 停止按钮先取消浏览器请求；服务端只能在可中断点感知。不要把当前实现说成“模型侧真正流式取消”。

## 第 2 周：解析、查询增强、重排与评测

### Day 08｜PDF / DOCX 解析边界

- **看：** [parser.py](../app/services/parser.py) 的 `extract_text()` 和 [docx_parser.py](../app/parse/docx_parser.py) 的 `extract_docx()`。
- **逻辑：** PDF 按页提取并保留“第 N 页”；DOCX 根据 Heading 样式加 `#` 标题标记，表格单独提取；上传入口限制文件大小、页数与解压后体积。扫描版 PDF 没有文字层会被拒绝。
- **跑：** `& $py -m pytest tests/test_api.py -q`，在 `/docs` 调用 `/v1/archives/upload` 上传自己的非敏感 TXT 或 DOCX。
- **讲清：** 这只是轻量文本解析；复杂表格、版面 bbox 与 OCR 没在主服务实现，不能说已跑过 MinerU 或训练过 LayoutLM。

### Day 09｜父子块与章节引用

- **看：** [chunker.py](../app/parse/chunker.py) 的 `build_chunks()`，再看 [retrieval.py](../app/services/retrieval.py) 如何用子块检索、返回父段落。
- **逻辑：** 每段原文是父块，200 字窗口是子块，相邻子块重叠 30 字。命中的子块按 `(doc_id, version, parent_id)` 去重，引用返回 `section_path/parent_id` 和父段落。
- **关键代码：** `if key not in best_by_parent or evidence.score > best_by_parent[key].score: best_by_parent[key] = evidence`。
- **跑：** `& $py -m pytest tests/test_agent_flow.py -q`；自己打印 `build_chunks()` 的 `parent_id/child_id/section_path`。
- **讲清：** 父块给回答上下文，子块提高定位精度；本地版本在查询时切块，大规模生产需要预建索引。

### Day 10｜权限、术语归一与拒答门槛

- **看：** [glossary.py](../app/retrieve/glossary.py)、[auth.py](../app/services/auth.py)、[retrieval.py](../app/services/retrieval.py) 的 `min_token_overlap`。
- **逻辑：** “提前还钱”先变成“提前还款”用于检索，但原问题保留给回答；权限过滤发生在打分之前；普通问题默认要求至少两个词片段重合，只有查询本身不足两个词片段时降低到其实际长度。
- **跑：** `& $py -m eval.run_offline --top-k 3`。观察两个负样本都拒答，再把 `min_token_overlap` 改为 1 重跑对比，最后恢复。
- **讲清：** 两词门槛是在 10 条虚构样本上验证的启发式规则，不是通用金融阈值。

### Day 11｜Multi-Query

- **看：** [retrieval_enhancement.py](../labs/retrieval_enhancement.py) 的 `QueryVariants`、`queries`、各查询 top5。
- **逻辑：** 同一个问题生成三种检索表达，分别召回后比较结果。离线模式用规则改写；`--use-llm` 才让模型生成三个查询。
- **跑：** `& $py -m labs.retrieval_enhancement`；准备好已配置模型时可跑 `& $py -m labs.retrieval_enhancement --use-llm`。
- **讲清：** 查询变多会增加检索成本；原问题与改写问题应保留关联，不能让改写凭空创造事实。

### Day 12｜HyDE

- **看：** 同一文件 [retrieval_enhancement.py](../labs/retrieval_enhancement.py) 的 `hypothetical_vector` 与 `mixed`。
- **逻辑：** 假设段落只用于构造检索向量，`mixed = 0.6 × HyDE + 0.4 × 原问题`，归一化后比较 top5；绝不把假设段落当成档案证据。
- **跑：** `& $py -m labs.retrieval_enhancement`；要完整体验模型改写和真实 BGE 向量，先装模型依赖，再跑 `& $py -m labs.retrieval_enhancement --use-llm --real-model`。
- **讲清：** HyDE 能扩展检索方向，也可能把问题带偏；需要 Golden Dataset 做 A/B 对照。真实模型路径未被默认启用。

### Day 13｜Reranker 与拒答

- **看：** [rerank_demo.py](../labs/rerank_demo.py) 的分数排序、[rerank.py](../app/retrieve/rerank.py) 的主服务可选接入。
- **逻辑：** 本地默认只打印词面分数；`--real-model` 使用 bge-reranker 对最多十个候选重排。`RERANK_MIN_SCORE` 低于阈值时拒答；阈值必须由标注数据定。
- **跑：** `& $py -m labs.rerank_demo`，安装模型后再跑 `& $py -m labs.rerank_demo --real-model`。记录 top1/top2 分数差及误拒答样例。
- **讲清：** Embedding 粗筛、Reranker 精排；模型分数不是通用概率，不应直接套别人阈值。

### Day 14｜Golden Dataset 与 RAGAS

- **看：** [golden.json](../eval/golden.json) 的十条正负样本、[run_offline.py](../eval/run_offline.py) 的统计分母、[run_ragas.py](../eval/run_ragas.py) 的四指标。
- **逻辑：** 离线回归分开计算“正样本引用命中/关键事实”和“负样本拒答”；`top_k=3/5` 只改一个变量。RAGAS 四指标分别看回答证据支持、答案相关性、上下文排序精度与覆盖率。
- **跑：** `& $py -m eval.run_offline --top-k 3`，再跑 `--top-k 5`，比较 `eval/results/`。RAGAS 请另建环境：`py -3.12 -m venv eval/.venv`，安装 `eval/requirements-ragas.txt`，用获授权的 API Key 跑 `eval/run_ragas.py`。
- **讲清：** 10 条虚构题只够验证流程；真实准确率必须说明问题抽样、标注、分母和拒答负样本。不要引用材料里未经实际核验的 60%、90% 等数字。

## 第 3 周：Prompt、追踪、Text2SQL 与代码审查

### Day 15｜Prompt YAML 版本

- **看：** [v1.yaml](../prompts/answer/v1.yaml)、[v2.yaml](../prompts/answer/v2.yaml)、[loader.py](../app/prompts/loader.py)。
- **逻辑：** 文件声明 `name/version/variables/system/user`。`PromptRegistry` 按名称与版本加载，用 Jinja2 `StrictUndefined` 渲染；文件修改时间变化后重新读取。原始证据作为变量值插入，不把证据当模板执行。
- **跑：** `& $py -m pytest tests/test_prompts.py -q`，然后 `& $py -m eval.compare_prompts`。
- **讲清：** `PROMPT_VERSION` 是发布开关；Prompt 变更与源码变更一样需要回归。当前是本地 YAML 管理，没有配置中心 UI。

### Day 16｜Prompt 回归对照

- **看：** [compare_prompts.py](../eval/compare_prompts.py) 的 v1/v2 循环与 `reference_contains`。
- **逻辑：** 默认只校验 YAML，不调用外部模型。显式 `--live` 后，只把虚构 Golden 样本送给已配置的模型；逐版本记录回答、引用 ID、关键事实是否出现。
- **跑：** `& $py -m eval.compare_prompts`；确认费用后可用 `& $py -m eval.compare_prompts --live --max-cases 2`。
- **讲清：** `reference_contains` 是粗糙的确定性检查，不等于 RAGAS 或人工正确率；模型版本、提示版本和样本集要一起留存。

### Day 17｜Langfuse Trace

- **看：** [langfuse_trace.py](../labs/langfuse_trace.py) 的 `CallbackHandler`、`config={"callbacks": [...]}` 和 `flush()`。
- **逻辑：** 仅用临时数据库里的虚构合同发一条 Trace；节点调用应形成可定位的执行轨迹。真实合同和客户问题不要直接上传到未获批准的云追踪服务。
- **跑：** `& $py -m pip install -r labs/requirements-langfuse.txt`；配置自己的 Langfuse 环境变量后跑 `& $py -m labs.langfuse_trace`，在界面记录截图。
- **讲清：** Trace 是一次问答，节点、模型和检索可形成子 Span；本仓库只提供显式运行的实验，不默认把主服务数据发送到 Langfuse。

### Day 18｜sqlglot AST 安全门

- **看：** [sql_guard.py](../labs/sql_guard.py) 的 `is_safe_select()` 和 `inject_row_filter()`，再看 [mschema.md](../labs/mschema.md)。
- **逻辑：** 先解析所有语句，必须恰好一条、根节点为 SELECT；遍历 AST 拒绝写操作与 `INTO`/锁定查询；只对单表查询注入 `tenant_id` 条件。
- **跑：** `& $py -m labs.sql_guard`，再跑 `& $py -m pytest tests/test_sql_guard.py -q`。
- **讲清：** AST 检查不能替代数据库只读账号、表列权限、查询超时。练习版明确拒绝 JOIN/CTE，不能声称处理了任意复杂 SQL。

### Day 19｜unidiff 解析代码行号

- **看：** [sample.diff](../labs/review/sample.diff)、[diff_parser.py](../labs/review/diff_parser.py) 的 `PatchSet` 与 `target_line_no`。
- **逻辑：** 评论必须落在 diff 的新增行，不能把旧文件行号误当作新文件行号；删除文件不生成新增行评论。
- **跑：** `& $py -m pytest tests/test_review_lab.py -q`，观察第 1 行被识别为新增的 `import os`。
- **讲清：** 审查链路的第一步是拿到可靠的文件路径、hunk 和新增行号；本实验没有接 GitLab webhook。

### Day 20｜ruff + 结构化 LLM 审查

- **看：** [lint.py](../labs/review/lint.py) 如何解析 ruff JSON、[reviewer.py](../labs/review/reviewer.py) 如何合并结果和校验行号。
- **逻辑：** 规则层先找确定性问题；可选模型层输出 Pydantic `Finding`。最终只保留新增行、去重，并标明来源 `ruff/llm`。LLM 只在显式 `--llm` 时发送练习 diff。
- **跑：** `& $py -m labs.review.reviewer`，应看到第 1 行 F401。确认发送的是虚构练习 diff 后可跑 `& $py -m labs.review.reviewer --llm`。
- **讲清：** 规则命中不是业务逻辑错误，模型判断也可能误报；当前代码未自动回写 PR 评论或阻断 CI。

### Day 21｜完整复盘与可展示证据

- **看：** [main.py](../app/main.py) → [graph.py](../app/agent/graph.py) → [retrieval.py](../app/services/retrieval.py) → [llm.py](../app/services/llm.py) → [README.md](../README.md)。
- **逻辑：** 用户问题进入 API；认证后由状态图规划、检索、分级与改写；只让有权限、在指定日期生效的档案进入上下文；生成答案后校验引用并记录审计。SQL 守卫和代码审查是仓库内的独立实验，不属于该问答 API。
- **跑：** `& $py -m pytest -q`、`& $py -m eval.run_offline --top-k 3`、`& $py -m labs.langgraph_control`、`& $py -m labs.milvus_demo`、在 `web/` 跑 `npm run build`。用自己的新租户跑 [run_demo.py](../examples/run_demo.py) 的合同问答；若已配置模型，可用 `& $py -m examples.smoke_live_model` 对虚构档案发起一次真实调用。
- **讲清：** 把功能分成“已本地验证”“需要你运行真实 BGE/RAGAS/Langfuse”“尚未实现的生产能力”。准备三分钟讲清状态图、权限过滤、引用与拒答，所有指标说出数据集和统计方式。
